## rexbox v0.0.33 (English)

The changes since **v0.0.32** (issue #91). **D3D8 presentation gains screen shaders (libretro GLSL)**, moved from repsp v0.0.24: the built-ins `crt`, `scanline`, `fsr`, `scalefx` and `anime4k`, user `.glsl`/`.glslp` files and `#pragma parameter`.

Issue #91 (`d2a3b19`, `3653b67`, `9294f57`):
* the post-processing pass in `PresentRenderTarget` (after SMAA and the gamma ramp, into the fitted rectangle);
* the GL-free catalog, preset and source assembly;
* the control contract `include/rexbox/hle/d3d8/d3d8_post_shader.h`, with `ResolvePostShaderDirectory` and `ChoosePostShader`;
* `rexbox_post_shader_probe` (93 checks), the guide `docs/guides/post-process-shaders.md`, and the notices.

For consumers:
* **No code change is needed.** With no shader chosen, the presentation GL calls are as before.
* To use shaders, the app calls `SetPostShaderDirectory` and `SetInitialPostShader` before the device is created, and its menu uses `GetPostShaderControl()` inside the overlay builder (see reexec/reEXCEED#20).
* Notices for re2DJ (BSD 3-Clause) and FSR 1.0, ScaleFX and Anime4K (MIT) are in `THIRD_PARTY_NOTICES.md`.

Verified in reEXCEED:
* Win32 x86 Release and Debug with 0 warnings, CTest 9/9, `rexbox_post_shader_probe` with 93 checks and 0 failures.
* In the window, shaders such as `crt` apply upright with the overlay unshaded at 60 fps; checked by the user.

Implemented by Antigravity; designed, reviewed and verified by Claude.
