## rexbox v0.0.32

이전 릴리스 **v0.0.31** 이후의 변경입니다(issue #89). **창에서 F10을 누르면 게스트 스레드 보고를 한 번 출력합니다.** 그림은 계속 나오는데 스레드 하나만 멈춘 경우를, 호출마다 기록하는 진단 없이 볼 수 있습니다.

### issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#89](https://github.com/reexec/rexbox/issues/89) | F10 → stall 모니터 스레드가 `ReportGuestThreads` 출력, 플랫폼 계약 `ConsumeThreadReportRequest()`. `REXBOX_STALL_REPORT=0`은 present 정지 보고만 끈다 | `b2a401f` |

### 소비자가 할 일

* **코드 변경은 필요 없다.** 플랫폼 계층을 직접 구현하는 소비자는 `platform::ConsumeThreadReportRequest()`를 더해야 한다(SDL 백엔드는 rexbox에 있다).
* `REXBOX_STALL_REPORT=0`이어도 모니터 스레드가 하나 돈다(100 ms마다 깨어남).

### 확인한 것

| 구성 | 확인 |
|---|---|
| reEXCEED | Win32 x86 Release·Debug 경고 0, CTest 7/7(rexbox probe 4개 포함). F10으로 스레드 보고가 나왔고, 이 보고로 음악 무음의 원인(reexec/reEXCEED#9)을 찾았다 |

이 변경은 사용자 결정으로 Claude가 설계·구현·검증했습니다.

## rexbox v0.0.32 (English)

The changes since **v0.0.31** (issue #89). **F10 in the window prints the guest thread report once**, so a thread that stops while the picture goes on can be inspected without per-call logging.

Issue: #89, F10 makes the stall monitor thread print `ReportGuestThreads`, through the platform contract `ConsumeThreadReportRequest()`; `REXBOX_STALL_REPORT=0` now turns off only the no-present report (`b2a401f`).

For consumers: **no code change is needed.** A consumer with its own platform layer must add `platform::ConsumeThreadReportRequest()` (rexbox has the SDL backend). With `REXBOX_STALL_REPORT=0` one monitor thread still runs, waking every 100 ms.

Verified in reEXCEED: Win32 x86 Release and Debug with 0 warnings, CTest 7/7 (including rexbox's four probes); F10 printed the thread report, which found the cause of the silent music (reexec/reEXCEED#9).

Designed, implemented and verified by Claude, by the user's decision.
