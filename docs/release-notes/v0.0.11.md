## rexbox v0.0.11

이전 릴리스 **v0.0.10** 이후의 변경입니다(issue #26). **rexbox가 lifter(xboxrecomp)에서 독립했습니다. xboxrecomp submodule이 없어졌고, lifter 체크아웃과 재컴파일 파이프라인은 타이틀이 가집니다.**

### issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#26](https://github.com/reexec/rexbox/issues/26) | xboxrecomp 의존 제거: lifter ABI 헤더는 `GEN_DIR`에서, 파이프라인은 타이틀로 | `87e309a`, `276c411`, `bac8e80`, `7505d5b`, `5c997b6` |

### 바뀐 것

* **ABI 헤더**: `src/recomp/recomp_abi.c`만 lifter의 `recomp_types.h`를 include한다. 이 파일은 `rexbox_add_recompiled_library`가 타이틀의 생성 코드와 함께, 그 `GEN_DIR`의 헤더로 컴파일한다(OBJECT 타깃 `<target>_abi`, `/W4`). 생성 코드가 부르는 lifter 이름의 콜백은 이 파일의 껍데기가 `recomp_bridge.cpp`의 `rexbox_bridge_*`로 넘긴다. 헤더가 선언한 콜백의 시그니처가 바뀌면 컴파일 에러가 난다.
* **지운 것**: `third_party/xboxrecomp` submodule, CMake 변수 `REXBOX_XBOXRECOMP_DIR`, 헤더 해시 검사, 라이선스 가드(`rexbox_check_license`, `cmake/rexbox_license.cmake`), `scripts/recomp/regenerate.py`, `check_hle_pops.py`, `find_pointer_targets.py`.
* **새 보조 스크립트**(평범한 데이터만 받는다): `hle_overrides.py`, `hle_pops.py`, `pointer_targets.py`. 테스트 `test_*.py`는 CI에서 돈다.
* 설계: [20261024-i026-drop-xboxrecomp](../design/20261024-i026-drop-xboxrecomp.md).

### 소비자가 할 일

* `set(REXBOX_XBOXRECOMP_DIR ...)`와 `rexbox_check_license(...)` 호출을 지운다(그대로 두면 configure가 실패한다).
* 파이프라인을 자기 저장소로 옮긴다. xboxrecomp를 실행하고 그 출력(`functions.json`, `/* ret N */`, `recomp_dispatch.c`)을 읽는 코드가 대상이며, rexbox의 `hle_overrides`, `hle_pops`, `pointer_targets`, `xbe_variant`를 부른다. reJSRF #117과 reCT3 #22의 `scripts/recomp/lifter.py`가 예다.
* `GEN_DIR`에 `recomp_types.h`가 있어야 한다(xboxrecomp lifter는 이미 그렇게 쓴다).
* **재생성은 필요 없다.** lift된 C, HLE override, 검사 스크립트의 출력이 이전과 바이트 단위로 같다.

### 확인한 것

| 구성 | 확인 |
|---|---|
| rexbox 단독, xboxrecomp 없는 새 configure, Win32 x86 Debug/Release | 경고 0, CTest 3/3, Python 테스트 6/6 |
| 옮긴 파이프라인으로 재생성(jsrf_us, jsrf_jp, ct3_jp) | lift된 C가 이전과 바이트 단위로 같다. `check_hle_pops`, `find_pointer_targets` 출력도 같다 |
| reCT3(upstream v0.15.0 헤더) | 빌드, West Coast 운전(그리기 약 790개, 59 fps) |
| reJSRF(fork 헤더) | 빌드, decomp 검사 129건 차이 0, D3D8 검사 14018건 차이 0, 부팅과 프레임 루프 |
| GNU ld(WSL, 합성 타이틀) | x86, x64 링크와 실행 |

## rexbox v0.0.11 (English)

Changes since **v0.0.10** (issue #26). **rexbox is independent of the lifter (xboxrecomp): the xboxrecomp submodule is gone, and the titles hold the lifter checkout and the recompilation pipeline.**

Issue: #26, removing the xboxrecomp dependency: the lifter ABI header comes from `GEN_DIR` and the pipeline moves to the titles (`87e309a`, `276c411`, `bac8e80`, `7505d5b`, `5c997b6`).

Changes:
* Only `src/recomp/recomp_abi.c` includes the lifter's `recomp_types.h`. `rexbox_add_recompiled_library` compiles it with the title's generated code, against the header in its `GEN_DIR` (OBJECT target `<target>_abi`, `/W4`).
* The callbacks generated code calls under the lifter's names are shells in that file, forwarding to `rexbox_bridge_*` in `recomp_bridge.cpp`. A changed signature of a callback the header declares fails to compile.
* Removed: the `third_party/xboxrecomp` submodule, the `REXBOX_XBOXRECOMP_DIR` CMake variable, the header hash check, the license guard (`rexbox_check_license`, `cmake/rexbox_license.cmake`), and `scripts/recomp/regenerate.py`, `check_hle_pops.py` and `find_pointer_targets.py`.
* New helper scripts that take plain data only: `hle_overrides.py`, `hle_pops.py` and `pointer_targets.py`, with `test_*.py` run in CI.
* Design: [20261024-i026-drop-xboxrecomp](../design/20261024-i026-drop-xboxrecomp.md).

Consumers:
* Delete `set(REXBOX_XBOXRECOMP_DIR ...)` and the `rexbox_check_license(...)` calls; configure fails while they remain.
* Move the pipeline into your own repository: the code that runs xboxrecomp and reads its output (`functions.json`, `/* ret N */`, `recomp_dispatch.c`), calling rexbox's `hle_overrides`, `hle_pops`, `pointer_targets` and `xbe_variant`. reJSRF #117 and reCT3 #22 (`scripts/recomp/lifter.py`) are examples.
* `GEN_DIR` must hold `recomp_types.h`; the xboxrecomp lifter already writes it there.
* **No regeneration is needed:** the lifted C, the HLE overrides and the check scripts' output are byte-identical to before.

Verified:
* rexbox on its own, from a fresh configure without xboxrecomp (Win32 x86 Debug/Release): 0 warnings, CTest 3/3, Python tests 6/6.
* Regenerating jsrf_us, jsrf_jp and ct3_jp with the moved pipeline: the lifted C, `check_hle_pops` and `find_pointer_targets` output are byte-identical to before.
* reCT3 (upstream v0.15.0 header): builds and drives in West Coast (about 790 draws, 59 fps).
* reJSRF (fork header): builds; the decomp check gives 129 cases with 0 differences, the D3D8 check 14018 cases with 0 differences; it boots and runs its frame loop.
* GNU ld (WSL, synthetic title): x86 and x64 link and run.
