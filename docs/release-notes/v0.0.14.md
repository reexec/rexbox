## rexbox v0.0.14

이전 릴리스 **v0.0.13** 이후의 변경입니다(issue #31). **생성 코드가 없는 트리에서 Linux 앱이 링크되지 않던 문제를 고쳤습니다.** v0.0.12가 더한 레지스터 접근 함수 대체 라이브러리가 GNU ld의 링크 순서에서 그 함수를 쓰는 `rexbox_recomp`보다 앞에 놓였습니다.

### issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#31](https://github.com/reexec/rexbox/issues/31) | 생성 코드 없는 분기의 GNU ld 링크 순서 | `2a1b774` |

### 바뀐 것

* `cmake/rexbox_recomp.cmake`: 생성 코드 없는 분기에서 `rexbox_recomp`가 `<target>_abi`에 의존하게 해(`target_link_libraries(rexbox_recomp PUBLIC ${target}_abi)`) 링크 줄에서 앞에 오게 한다. MSVC에는 영향이 없다.

### 소비자가 할 일

* 없다. 게임 데이터 없는 Linux 트리(CI)에서도 앱이 링크된다.

## rexbox v0.0.14 (English)

Changes since **v0.0.13** (issue #31). **Fixes the Linux application's link failure in a tree without generated code**: the accessor stand-in library v0.0.12 added came before its user, `rexbox_recomp`, in GNU ld's link order.

Issue: #31, the GNU ld link order of the no-generated-code branch (`2a1b774`).

Changes: in `cmake/rexbox_recomp.cmake`'s no-generated-code branch, `rexbox_recomp` now depends on `<target>_abi` (`target_link_libraries(rexbox_recomp PUBLIC ${target}_abi)`), which orders it first on the link line; MSVC is unaffected.

Consumers: nothing to do; the application links in a Linux tree without game data (CI).

Verified: rexbox Linux x64 Debug (GCC 13) with 0 warnings and CTest 4/4; reJSRF Linux x64 Debug without generated code goes from 17 undefined references to 0, links and passes the smoke check; rexbox Win32 x86 Debug with 0 warnings and `rexbox_recomp_probe` 8/8. User: approved the merge (part of nworkers/reJSRF#119).
