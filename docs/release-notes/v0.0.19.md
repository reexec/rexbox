## rexbox v0.0.19

이전 릴리스 **v0.0.18** 이후의 변경입니다(issue #42, #43). **render state로 쓴 combiner 상수를 픽셀 셰이더 상수로 쓰고, 다시 채워지지 않는 스트림 루프 버퍼를 기본 로그에 보고합니다.**

### issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#42](https://github.com/reexec/rexbox/issues/42) | render state로 쓴 combiner 상수(`COMBINER_FACTOR0/1`, 최종 상수) | `4f3e5b8` |
| [#43](https://github.com/reexec/rexbox/issues/43) | 스트림 루프 버퍼 정지 보고, 게스트 스레드 상태와 호스트 콜스택 | `87e7017`, 이 릴리스의 마지막 커밋 |

### 바뀐 것

* **D3D8**: `SetPixelShader` 뒤에 render state로 쓴 `COMBINER_FACTOR0/1`(단계별)과 최종 combiner 상수가 그 단계의 c0/c1이 된다. 정의의 상수와 `SetPixelShaderConstant`보다 우선한다([설계 i042](../design/20261103-i042-combiner-factors.md)). d3d8 probe 220 → 223.
* **DSOUND**: 16 KiB 이상의 루프 버퍼가 스트림으로 쓰이다가 같은 내용을 8바퀴, 2초 넘게 반복하면 `[dsound] buffer ... its writer stopped`를 한 번 보고한다. 이어서 게스트 스레드 상태와 호스트 콜스택을 출력한다([설계 i043](../design/20261103-i043-stream-stall-report.md)).
* **runtime·플랫폼**: `ReportGuestThreads`, 플랫폼 계약 `stack_report.h`(Linux 구현, Win32는 아직 없음). 정지 보고(present 정지)도 호스트 콜스택을 출력한다.
* 문서: ARCHITECTURE, 설계·작업 지시·작업 로그 i042, i043.

### 소비자가 할 일

* submodule을 올린다. 공개 계약은 늘기만 했고 재생성은 필요 없다.
* render state로 combiner 상수를 쓰는 타이틀은 그 그리기의 색과 알파가 바뀐다(원본과 같아지는 방향). 화면을 확인한다.
* Linux에서 게스트 스레드는 SIGUSR2를 진단 보고에 쓴다. 타이틀이 SIGUSR2를 쓰지 않아야 한다.

## rexbox v0.0.19 (English)

Changes since **v0.0.18** (issues #42, #43). **Combiner constants written as render states become the pixel shader constants, and a streamed loop buffer no longer refilled is reported in the default log.**

Issues: #42, combiner constants written as render states (`COMBINER_FACTOR0/1`, final constants) (`4f3e5b8`); #43, the stalled-stream report with guest thread states and host stacks (`87e7017` and the last commit of this release).

Changes: D3D8: per-stage `COMBINER_FACTOR0/1` and the final combiner constants written as render states after `SetPixelShader` become that stage's c0/c1, over the definition and `SetPixelShaderConstant` ([design i042](../design/20261103-i042-combiner-factors.md)); d3d8 probe 220 → 223. DSOUND: a loop buffer of 16 KiB or more used as a stream that then replays the same content for 8 laps and over 2 s is reported once (`[dsound] buffer ... its writer stopped`), followed by the guest thread states and host stacks ([design i043](../design/20261103-i043-stream-stall-report.md)). Runtime and platform: `ReportGuestThreads` and the platform contract `stack_report.h` (Linux; Win32 not yet); the present-stall report prints host stacks too. Documents: ARCHITECTURE, design, work order and work log i042 and i043.

Consumers: move the submodule; the public contract only grew and no regeneration is needed. A title writing combiner constants as render states sees those draws' color and alpha change (toward the original); check the picture. On Linux the guest threads use SIGUSR2 for diagnostic reports; the title must not use SIGUSR2.

Verified: d3d8 probe 223/223; the consumer reCT3 Linux x64 Release with 0 warnings and CTest 7/7; in reCT3's demo the wheel flames are drawn (user confirmed) and the stalled-stream report fires once, with no false positive for static loops or silence.
