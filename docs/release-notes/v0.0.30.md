## rexbox v0.0.30

이전 릴리스 **v0.0.29** 이후의 변경입니다(issue #83). **새 텍스처를 만들 때의 멈춤이 사라집니다.** 2D 텍스처의 저장소를 `glTexStorage2D`로 한 번에 정하고, 데이터는 sub-image로 올립니다. 레벨마다 `glTexImage2D`/`glCompressedTexImage2D`로 정하던 예전 경로는 작은 DXT 텍스처 하나에 3~14 ms를 쓰기도 했습니다.

### issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#83](https://github.com/reexec/rexbox/issues/83) | 느린 프레임의 단계별 시간·양·`oncpu`(정밀 스레드 CPU 시간), 텍스처 저장소를 미리 정함 | `ef357d5`, `926a76d` |

### 소비자가 할 일

* **코드 변경은 필요 없다.** `glTexStorage2D`가 없는 호스트와 3D 텍스처는 예전 경로를 쓴다.
* 플랫폼 계층을 직접 구현하는 소비자는 `platform::ThreadCpuPreciseNanoseconds()`를 더해야 한다(Win32, Linux는 rexbox에 있다).

### 확인한 것

| 구성 | 확인 |
|---|---|
| rexbox | CTest 4/4 |
| reCT3 Win32 x86 Release | CTest 7/7. 주행 중 느린 프레임(20 ms 넘음) 189 → 80·54, 느린 프레임의 텍스처 GL 시간 190.7 ms → 0.1 ms. 캡처 정상 |

이 변경은 Antigravity가 구현하고 Claude가 설계·검토·측정했습니다.

## rexbox v0.0.30 (English)

The changes since **v0.0.29** (issue #83). **Making new textures no longer stalls.** 2D textures get their storage at once with `glTexStorage2D` and their data through sub-image calls; the old path, defining each level with `glTexImage2D`/`glCompressedTexImage2D`, sometimes spent 3–14 ms on one small DXT texture.

Issue: #83, per-phase time, volume and `oncpu` (precise thread CPU time) in slow frames, and texture storage up front (`ef357d5`, `926a76d`).

For consumers: **no code change is needed.** Hosts without `glTexStorage2D` and 3D textures use the old path. A consumer with its own platform layer must add `platform::ThreadCpuPreciseNanoseconds()` (rexbox has Win32 and Linux).

Verified: rexbox CTest 4/4; reCT3 Win32 x86 Release, CTest 7/7. Driving slow frames (over 20 ms) fell from 189 to 80 and 54, and the texture GL time in slow frames from 190.7 ms to 0.1 ms; captures were correct.

Implemented by Antigravity; designed, reviewed and measured by Claude.
