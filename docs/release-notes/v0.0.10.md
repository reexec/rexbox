## rexbox v0.0.10

이전 릴리스 **v0.0.9** 이후의 변경입니다(issue #23 1차). **D3D8 그리기 하나의 CPU 비용을 줄였습니다. 소비자 reCT3의 운전 화면(그리기 약 810개)에서 D3D8 그리기 단계가 16~24%, 표시 스레드 CPU가 프레임당 1.8~4 ms 줄었습니다.**

### issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#23](https://github.com/reexec/rexbox/issues/23) | 그리기 하나의 CPU 비용, 1차(issue는 열린 채 다음 단계가 이어진다) | `35ca8f8`, `7634f9e`, `c46c9f2`, `052aee8` |

### 바뀐 것

* **상태 읽기**: 렌더·텍스처 상태 블록의 호스트 포인터와 슬롯 수를 주소를 찾을 때 보관해, 읽기마다 load 하나로 한다.
* **프로그램 조회**: 네 프로그램 map이 앞 조회와 키가 같으면 해시와 탐색 없이 앞 결과를 쓴다.
* **인덱스**: push-buffer 조각의 16비트 인덱스를 재사용 버퍼에서 한 번에 변환한다. 인덱스는 `GL_COPY_WRITE_BUFFER`로 올린다.
* **범위별 VAO**: 캐시된 정점 범위마다 VAO를 둔다. element 버퍼는 그리기 직전에 VAO마다 바인딩한다. `glDeleteVertexArrays`가 필수 GL 함수가 되었다.
* **uniform**: `UniformCache`는 위치로 바로 찾는다. combiner 상수는 정의나 픽셀 셰이더 상수(새 버전 번호 `PixelShaderConstantsVersion`)가 바뀔 때만 계산한다. 단계마다 앞 sampler를 다시 쓴다.
* **진단**: `REXBOX_D3D8_PROFILE` 줄에 같은 프레임 안 재비교 수 `(N again)`이 붙는다.
* **설계 변경**([설계 §3.1](../design/20261021-i023-draw-cpu-cost.md)): 스냅샷 메모는 render target 사본 갱신을 건너뛰게 되어 위의 키 비교로 바꿨다. 정점 비교 생략은 재비교가 4%뿐이라 하지 않았다.

### 소비자가 할 일

* 계약 변경 없음. 재생성 없이 다시 빌드하면 된다. GL 3.0 / GLES 3.0의 `glDeleteVertexArrays`가 있어야 한다.

## rexbox v0.0.10 (English)

Changes since **v0.0.9** (first pass of issue #23). **The CPU cost of one D3D8 draw is lower: in the consumer reCT3's driving scene (about 810 draws) the D3D8 draw phases fell 16–24% and the presenting thread's CPU 1.8–4 ms per frame.**

Issue: #23, the CPU cost of one draw, first pass (the issue stays open for the next steps; `35ca8f8`, `7634f9e`, `c46c9f2`, `052aee8`).

Changes: render- and texture-state reads go through the blocks' host pointers and slot count kept when the addresses are found (one load per read); the four program maps return the previous result without hashing and searching when the key matches the previous lookup; push-buffer fragments' 16-bit indices are converted in one pass into a reused buffer, and indices are uploaded through `GL_COPY_WRITE_BUFFER`; each cached vertex range has its own VAO, with the element buffer bound per VAO just before the draw (`glDeleteVertexArrays` is now a required GL function); `UniformCache` is indexed by location, combiner constants are formed only when the definition or the pixel-shader constants (a new version number, `PixelShaderConstantsVersion`) change, and each stage reuses its previous sampler; the `REXBOX_D3D8_PROFILE` line gains `(N again)`, ranges compared again within a frame. Design changes ([design section 3.1](../design/20261021-i023-draw-cpu-cost.md)): the snapshot memo would skip render-target copy refreshes and became the key comparison above; skipping vertex compares was dropped (only 4% repeat).

Consumers: no contract change; rebuild without regeneration. GL 3.0 / GLES 3.0's `glDeleteVertexArrays` must be present.

Verified: Win32 x86 Release in the consumer reCT3's tree with no build errors, CTest reCT3 5/5 and rexbox 3/3. reCT3 driving, slow machine: 18.5 → 20.7 fps, CPU 32.0 → 28.0 ms, D3D8 phases 22.7 → 17.2 ms; fast machine: 28.2 → 27.8 fps (vblank quantization), CPU 23.5 → 21.7 ms, D3D8 phases 13.7 → 11.5 ms. Dumps of attract-demo frame 1500 and driving frame 2700 match except for moving objects. Linux is **not verified**: CI's Linux x86 job fails while installing packages, as since v0.0.3.
