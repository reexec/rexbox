## rexbox v0.0.7

이전 릴리스 **v0.0.6** 이후의 변경입니다(issue #18). **`D3DDevice_Swap`이 플립을 예약하고 돌아옵니다. Swap 뒤에 스스로 vblank를 기다리는 타이틀이 프레임마다 vblank 두 개를 쓰지 않습니다.**

### issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#18](https://github.com/reexec/rexbox/issues/18) | Swap의 플립 예약(설계·작업 지시, 구현, 작업 로그) | `16db964`, `97dcae3` |

### 바뀐 것

* **플립 예약**([설계 i018-swap-queues-flip](../design/20261021-i018-swap-queues-flip.md)): `WaitForPresentInterval`이 `QueuePresent`가 됐다. 앞 present의 vblank가 아직 오지 않았을 때만 그때까지 자고, 이 present의 vblank를 예약하고 돌아온다(대기열에 플립 하나). 예전에는 `Swap`이 언제나 vblank까지 잤다.
* **정렬 위상**: 호스트 vsync 정렬 뒤 가상 vblank가 호스트 blank보다 1 ms 뒤(`kAlignLag`)에 온다. 예전에는 3 ms 앞(`kAlignLead`)이었다.

### 소비자가 할 일

* 계약 변경 없음. `Swap`만 부르고 스스로 기다리지 않는 타이틀은 지금처럼 vblank 하나에 프레임 하나다.

| reCT3 타이틀 화면 | 29.5 fps(`wait` 32 ms) → 창·vsync 60.0~60.1, 숨김 60.0, vsync 끔 60.0 |
| reCT3 데모 도시 장면 | 22.4~24.2 → 39.7~41.6 fps |
| reCT3 운전 | 14.4 → 19.1 fps(게임 시간은 present당 1/60초, 이 기계에서는 CPU가 한계) |

| Linux | **확인 못 함**. CI의 Linux x86 작업이 패키지 설치에서 실패한다(v0.0.3부터 같음) |

## rexbox v0.0.7 (English)

Changes since **v0.0.6** (issue #18). **`D3DDevice_Swap` queues the flip and returns, so a title that waits for the vblank itself after Swap no longer spends two vblanks per frame.**

Issue: #18, Swap queues the flip (design and work order, implementation, work log; `16db964`, `97dcae3`).

Changes: queued flips ([design i018-swap-queues-flip](../design/20261021-i018-swap-queues-flip.md)): `WaitForPresentInterval` became `QueuePresent`, which sleeps only while the previous present's vblank has not come, queues this present's vblank and returns (one flip in the queue); `Swap` used to sleep to the vblank every time. Alignment phase: after host vsync alignment the virtual vblank comes 1 ms after the host's blank (`kAlignLag`) instead of 3 ms before it (`kAlignLead`).

Consumers: no contract change; a title that only calls `Swap` and never waits itself still gets one frame per vblank.

Verified: Win32 x86 Release with no build errors and `ctest` 5/5. reCT3's title screen went from 29.5 fps (`wait` 32 ms) to 60.0–60.1 in a window with vsync, 60.0 hidden and 60.0 with vsync off; its demo city scenes from 22.4–24.2 to 39.7–41.6 fps; driving from 14.4 to 19.1 fps (game time is 1/60 s per present, and the CPU is the limit on that machine). The host vsync alignment was **not exercised**: in a window on the test machine the host swap never blocked for 1 ms or more. Linux is **not verified**: CI's Linux x86 job fails while installing packages, as since v0.0.3.
