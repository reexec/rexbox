## rexbox v0.0.16

이전 릴리스 **v0.0.15** 이후의 변경입니다(issue #36). **Linux에서 soft-dirty 쓰기 추적을 쓰지 않습니다.** soft-dirty를 지원하는 커널에서는 쓰인 페이지를 물을 때마다 프로세스 전체를 지워(`/proc/self/clear_refs`) 3D 장면이 크게 느려졌습니다(소비자 reJSRF의 데모 약 4 fps → 60 fps).

### issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#36](https://github.com/reexec/rexbox/issues/36) | Linux에서 soft-dirty 쓰기 추적 제거 | `094b233` |

### 바뀐 것

* `src/platform/linux/virtual_memory_linux.cpp`: `AllocateVirtualMemory`가 `track_writes`를 무시하고, `TakeWrittenPages`는 늘 false다. `GuestMemory::TracksWrites()`가 false가 되어 D3D8은 정점·인덱스 범위를 늘 비교한다(WSL2와 같은 경로). 묻지 않은 범위의 쓰기 기록이 지워지던 문제도 함께 없어진다([설계 i036](../design/20261027-i036-linux-write-tracking.md)).
* 문서: `ARCHITECTURE.md`, 설계 i004(대체됨 표시), Linux 가이드.

### 소비자가 할 일

* submodule을 올린다. 공개 계약은 바뀌지 않았고 재생성도 필요 없다. Win32는 바뀌지 않았다.

| 사용자 | 방안 A 승인 |

## rexbox v0.0.16 (English)

Changes since **v0.0.15** (issue #36). **Linux no longer uses soft-dirty write tracking.** On kernels with soft-dirty, every written-page query cleared the whole process (`/proc/self/clear_refs`), slowing 3D scenes badly (the consumer reJSRF's demo went from about 4 fps to 60 fps).

Issue: #36, soft-dirty write tracking removed on Linux (`094b233`).

Changes: in `src/platform/linux/virtual_memory_linux.cpp`, `AllocateVirtualMemory` ignores `track_writes` and `TakeWrittenPages` always returns false, so `GuestMemory::TracksWrites()` is false and D3D8 always compares vertex and index ranges (the WSL2 path); the loss of write records for ranges not queried goes with it ([design i036](../design/20261027-i036-linux-write-tracking.md)). Documents: `ARCHITECTURE.md`, design i004 (marked replaced), the Linux guide.

Consumers: move the submodule. The public contract is unchanged and no regeneration is needed; Win32 is unchanged.

Verified: Linux x64 Release and Debug (Ubuntu 26.04, GCC 15) with 0 warnings and `ctest` 4/4; in the consumer reJSRF x64 Release, the demo at 59.4–60.0 fps (presenting-thread CPU 2.1–3.2 ms) and no difference in `rejsrf_decomp_check` and `rejsrf_d3d8_check`. User: approved option A.
