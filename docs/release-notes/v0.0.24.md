## rexbox v0.0.24 (English)

The changes since **v0.0.23** (issues #67–#69). **A title that keeps recreating textures (Pump It Up: Exceed in reexec/reEXCEED) no longer runs guest memory out.**

Issues:
- #67: `D3D_DestroyResource` and `Release` free a title-made resource through the library body; `RunLiftedOriginal()` lets an HLE export run the lifted original (`2286b13`).
- #68: contiguous-memory frees and queries fold the `0x80000000` and `0xF0000000` window addresses (`ce95a96`).
- #69: `NtQueryFullAttributesFile`, kernel import 210 (`a514e79`).

For consumers: **no code change is needed.** To have title-made resources (inline texture creation and the like) freed, the title profile binds the XDK internal `D3D_DestroyResource` (the address of `D3D_DestroyResource_0__LTCG_edi1`); without the binding nothing changes.

Known limits: a second guest thread's GL work has no effect (#65).

Verified:
- Win32 x86 Debug and Release (in the reEXCEED tree): 0 errors and 0 warnings, CTest 7/7.
- reEXCEED (window shown, audio, keyboard): song select → gameplay (BGA) → GAME OVER → SELECT MODE, with no memory exhaustion and no stop in 181 s.
