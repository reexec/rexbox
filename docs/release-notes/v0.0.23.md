## rexbox v0.0.23

이전 릴리스 **v0.0.22** 이후의 변경입니다(issue #62~#64). **로딩 화면을 다른 스레드에서 그리는 타이틀(reexec/reEXCEED의 Pump It Up: Exceed)이 창을 띄운 채 멈추지 않습니다.**

### issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#62](https://github.com/reexec/rexbox/issues/62) | 창 제목과 이벤트 펌프는 창을 만든 스레드에서만(Windows의 교차 스레드 `SetWindowTextW` 교착) | `9e2fa23` |
| [#63](https://github.com/reexec/rexbox/issues/63) | `RtlLeaveCriticalSection`이 첫 대기자에게 소유권을 넘긴다(재진입을 반복하는 스레드가 대기자를 굶기지 않음) | `b61f4ea` |
| [#64](https://github.com/reexec/rexbox/issues/64) | `GetVideoMemoryInfo`의 GL 오류 비우기에 상한(GL 컨텍스트가 없는 스레드에서 끝나지 않던 루프) | `a0744fb` |

### 소비자가 할 일

* **코드 변경은 필요 없다.**
* 다른 스레드의 present가 바꾼 창 제목(FPS)은 창을 만든 스레드가 다음에 present하거나 펌프할 때 보인다.
* 다른 스레드의 `PumpDisplayEvents`는 아무것도 하지 않는다.
* 임계 구역은 대기 순서대로 넘어간다.

### 알려진 한계

* GL 컨텍스트는 디스플레이를 만든 스레드에서만 current다. 두 번째 게스트 스레드의 GL 작업은 효과가 없다([#65](https://github.com/reexec/rexbox/issues/65)).
* Windows의 stall 보고에는 호스트 스택이 없다.

## rexbox v0.0.23 (English)

The changes since **v0.0.22** (issues #62–#64). **A title that draws its loading screen from another thread (Pump It Up: Exceed in reexec/reEXCEED) no longer stops with the window shown.**

Issues:
- #62: the window title and the event pump only on the window's thread, which fixes a cross-thread `SetWindowTextW` deadlock on Windows (`9e2fa23`).
- #63: `RtlLeaveCriticalSection` hands the section to the first waiter, so a thread that re-enters in a loop no longer starves it (`b61f4ea`).
- #64: a bound on the GL error drain in `GetVideoMemoryInfo`, which never ended on a thread without the GL context (`a0744fb`).

For consumers: **no code change is needed.** A window title (frame rate) set by a present on another thread shows at the window thread's next present or pump. `PumpDisplayEvents` does nothing on other threads. Critical sections pass in waiting order.

Known limits:
- The GL context is current only on the thread that created the display, so a second guest thread's GL work has no effect ([#65](https://github.com/reexec/rexbox/issues/65)).
- The Windows stall report has no host stacks.

Verified:
- Win32 x86 Debug and Release (in the reEXCEED tree): 0 errors and 0 warnings, CTest 7/7 (with the recomp, kernel, dsound and d3d8 probes).
- reEXCEED (window shown, audio, keyboard): START at the title → SELECT MODE → song select → difficulty select, with no stop in 120 s.
