## rexbox v0.0.21

이전 릴리스 **v0.0.20** 이후의 변경입니다(issue #46). **CI와 릴리스 워크플로의 Linux x86 작업이 다시 패키지를 설치합니다.** 2026-11-02부터 glib 2.80.0-6ubuntu3.10 때문에 설치가 멈춰, main의 CI가 실패하고 v0.0.17~v0.0.20의 GitHub Release가 만들어지지 않았습니다.

### issue

| issue | 내용 | 커밋 |
|---|---|---|
| [#46](https://github.com/reexec/rexbox/issues/46) | Linux x86 작업의 `libglib2.0-dev:i386` 설치 실패 | `i046-ci-glib-i386` 브랜치 |

### 바뀐 것

* `ci.yml`, `release.yml`: x86 작업이 i386 개발 패키지 전에 amd64 `libglib2.0-dev-bin`과 `qemu-user`를 설치한다. glib 3.10의 개발 파일은 `python3 | qemu-user | qemu-user-static`에 의존하는데, i386 패키지에서 이 `python3`는 i386 `python3`다. 목록을 한 번에 주면 apt가 그것을 골라 러너의 amd64 Python과 충돌하고 포기했다([작업 로그](../work-logs/20261103-i046-ci-glib-i386.md)).
* `docs/guides/linux-setup-and-build.md`: i386 설치에 같은 선행 설치.

### 소비자가 할 일

* 코드 변경은 없다. submodule을 올려도 되고 그대로 두어도 된다.
* 자기 CI나 Linux 기계에서 `libpulse-dev:i386`을 설치한다면 같은 선행 설치를 한다.

## rexbox v0.0.21 (English)

Changes since **v0.0.20** (issue #46). **The Linux x86 jobs of CI and the release workflow install their packages again.** Since 2026-11-02 glib 2.80.0-6ubuntu3.10 stopped the install, so CI on main failed and no GitHub Release was made for v0.0.17–v0.0.20.

Issue: #46, the Linux x86 jobs' `libglib2.0-dev:i386` install failure (branch `i046-ci-glib-i386`).

Changes: `ci.yml` and `release.yml` install the amd64 `libglib2.0-dev-bin` and `qemu-user` before the i386 development packages in the x86 jobs. glib 3.10's development files depend on `python3 | qemu-user | qemu-user-static`, and for an i386 package that `python3` is `python3:i386`; given the whole list at once apt took it, clashed with the runner's amd64 Python and gave up ([work log](../work-logs/20261103-i046-ci-glib-i386.md)). `docs/guides/linux-setup-and-build.md` adds the same step to the i386 install.

Consumers: no code changes; moving the submodule is optional. A consumer CI or Linux machine installing `libpulse-dev:i386` needs the same first step.

Verified: the branch's `ci.yml` passes all six jobs.
