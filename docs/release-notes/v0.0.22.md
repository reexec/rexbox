### 소비자가 할 일

* **코드 변경은 필요 없다.** `KernelConfig::image_file_name`은 기본값 `default.xbe`다. 실제로 불러온 XBE 이름을 넘기면 `XeImageFileName`이 그것을 가리킨다.
* `IsKernelThunkVa`는 이제 `0xFE000000` 이상 `0xFF000000` 미만이다(`0xFF000000~`는 HLE 메서드 합성 주소, `kHleMethodVaBase`).
* `DirectSoundDoWork`는 이제 스트림 완료를 전달한다(전에는 아무것도 하지 않았다).
* 렌더 상태 배치: 4134보다 큰 deferred 블록을 받아들인다. 4134·4531 타이틀의 결과는 같다(d3d8 probe의 4531 검사 그대로).
* 타이틀이 XDK 내부 변수 `D3D_g_Device`, `D3DDevice__m_Transform_OFFSET`, `D3DRS_SampleAlpha`를 바인딩하면 해당 동작이 켜진다(바인딩하지 않으면 전과 같다).

### 알려진 한계

* 디바이스 푸시 버퍼의 NV2A 메서드 중 해석하지 않은 것이 남아 있다(보고만 한다).
* 받기만 하는 설정이 있다: DSOUND 스트림의 mix bin·필터·피치 등, 출력(submix) 버퍼, D3D8 오버레이, 시저.
* Debug 빌드에서 패드가 연결될 때 게스트 스레드에서 `SDL_PumpEvents`를 불러 SDL 단언에 걸린다(후속 issue).

## rexbox v0.0.22 (English)

The changes since **v0.0.21** (issues #49–#58, #60). **An XDK 5849 LTCG title (Pump It Up: Exceed in reexec/reEXCEED) boots and draws its opening movie and title screen.**

Issues, as in the table above: #49 the kernel data export `XeImageFileName` with `KernelConfig::image_file_name` and `DataExportAddress` (`3748866`); #50 D3D8LTCG register-convention variants, `Direct3D_CreateDevice_4__LTCG_eax1_ecx3` and twelve through a table-driven adapter (`f49d055`, `b1d9cd4`); #51 the device push buffer the title writes itself, `MakeRequestedSpace`/`KickOff` (`b1d9cd4`); #52 kernel `KeQueryPerformanceCounter`/`Frequency`, `XcHMAC`, `MmQueryStatistics`, `XcRC4Key`/`XcRC4Crypt` (`8c250fc`); #53 XNET offline (`616ff96`); #54 DSOUND streams and the HLE method synthetic addresses at `0xFF000000` (`f3e00e2`, `b1cbfcd`); #55 `rexbox_dsound_apu_sample_count()` (`3a16fb2`); #56 the D3D8 queries, vertex-constant and DSOUND voice exports a title reaches directly, the bound static LTCG device and `Lock2DSurface` LTCG (`9a8f164`, `b1cbfcd`); #57 state blocks as HLE snapshots (`b1cbfcd`); #58 YUY2/UYVY textures and the world/view transforms in captures (`82719c8`, `84fbd7f`); #60 the XDK 5849 render-state layout, the absent specular's alpha and the device transform array LTCG writes (`9b46414`).

For consumers: **no code change is needed.** `KernelConfig::image_file_name` defaults to `default.xbe`; pass the XBE actually loaded for `XeImageFileName` to name it. `IsKernelThunkVa` now covers `0xFE000000` up to `0xFF000000` (from `0xFF000000` on are HLE method addresses, `kHleMethodVaBase`). `DirectSoundDoWork` now delivers stream completions (it did nothing before). The render-state layout accepts deferred blocks larger than 4134's; 4134 and 4531 titles get the same results (the d3d8 probe's 4531 checks are unchanged). Binding the XDK internals `D3D_g_Device`, `D3DDevice__m_Transform_OFFSET` and `D3DRS_SampleAlpha` turns their behavior on; without them nothing changes.

Known limits: some NV2A methods in the device push buffer are still only reported; some settings are accepted only (DSOUND stream mix bins, filters, pitch and the like, output (submix) buffers, the D3D8 overlay, scissors); in Debug builds a pad's arrival calls `SDL_PumpEvents` on a guest thread and trips an SDL assertion (a follow-up issue).

Verified: Win32 x86 Debug and Release (in the reEXCEED tree) with 0 errors and 0 warnings, probes recomp 8, kernel 103, dsound 73 and d3d8 234 checks with 0 failures; reEXCEED (Release, hidden, no audio) runs past 120 s and draws the opening movie and the title screen.
