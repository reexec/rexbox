# 설계: 밀집 장면의 VAO 바인드 비용 (issue #78)

상태: 설계(1단계: 실험 스위치). 소비자: reexec/reCT3#41. 이전: [i023 draw CPU 비용](20261021-i023-draw-cpu-cost.md), [i076 GL 시간](20261107-i076-gl-call-time.md).

## 1. 요구사항

Crazy Taxi 3 주행(Win32 x86 Release, RTX 4090)에서 `REXBOX_GL_CALLS=time`으로 재 보니, 밀집 장면의 GL 드라이버 시간은 거의 전부 `glBindVertexArray`였다. 바인드 한 번의 비용도 draw 수와 함께 커졌다.

| draw/프레임 | fps | cpu ms/프레임 | GL ms/프레임 | `glBindVertexArray` ms (호출) |
|---|---|---|---|---|
| 900 | 59.0 | 7.55 | 1.41 | 0.89 (870) |
| 999 | 50.4 | 10.13 | 3.39 | 2.75 (951) |
| 1584 | 30.6 | 17.37 | 7.44 | 6.66 (1528) |

나머지 GL 호출은 모두 합쳐 프레임당 0.8 ms 미만이다.

## 2. 지금 구조 (#23, `7634f9e`)

* 캐시된 정점 구간(`g_vertex_ranges`)마다 VAO(`CachedRange::array`)가 하나씩 있다. `PrepareVertexData`가 그 VAO를 바인드하고, 바뀐 구간은 `glBufferData`로 저장소를 다시 정한다.
* 캐시된 인덱스 구간(`g_index_ranges`)마다 버퍼가 하나씩 있다. `BindElementBuffer`가 draw 직전에 지금 VAO의 요소 바인딩을 그 버퍼로 바꾼다.
* 캐시되지 않은 정점은 스트림 VAO(`g_stream_array`)와 스트림 버퍼를 쓴다.
* 그래서 밀집 장면에서는 draw 대부분이 다른 VAO를 바인드하고, 그 VAO의 요소 바인딩도 바꾼다. 1584 draw 창에서 `glBindBuffer`는 프레임당 2810번이었다.
* #23은 이것을 작은 이득으로 쟀다(attributes −1.0 ms, VAO 바인드 +0.8 ms). 이 드라이버와 이 장면에서는 지금 가장 큰 비용이다.

## 3. 1단계: 실험 스위치 `REXBOX_GL_VAO`

드라이버가 무엇에 비용을 매기는지 가린다. 기본값은 지금 그대로다.

* `range`(기본, 변수 없음): 지금의 구간별 VAO.
* `single`: 모든 draw가 스트림 VAO 하나를 쓴다(#23 이전의 경로).
  * `PrepareVertexData`는 구간의 VAO 대신 `g_stream_array`를 바인드하고, 구간 버퍼를 `GL_ARRAY_BUFFER`에 바인드한다.
  * 속성 포인터는 `SetAttribute`의 기존 비교가 버퍼나 오프셋이 바뀌었을 때만 다시 보낸다.
  * 요소 바인딩도 기존 `BindElementBuffer`가 같은 VAO에서 바뀔 때만 보낸다.
  * 구간별 `CachedRange::array`는 만들지 않는다.
* 스위치는 시작할 때 한 번 읽는다. 첫 draw 전에 정해지므로 경로가 중간에 섞이지 않는다.

측정: reCT3 주행에서 `range`와 `single`을 같은 장면으로 비교한다(`REXBOX_GL_CALLS=time REXBOX_D3D8_PROFILE=600`).
* 진입점별 GL 시간: `glBindVertexArray`, `glVertexAttribPointer`, `glBindBuffer`.
* 단계 시간: upload, attributes.
* 밀집 구간의 fps와 cpu.

## 4. 2단계 (1단계 결과에 따라)

* `single`이 이기면 기본으로 삼고 `range`를 걷어낼지 정한다. 이때 GLES 3.0·WebGL 2에서도 같은지가 남는다.
* `single`도 비싸면(포인터 재전송 비용) GL 4.3 / ES 3.1의 정점 속성 바인딩을 검토한다. 레이아웃마다 VAO 하나를 두고, draw마다 `glBindVertexBuffer`를 쓰는 방식이다.
* 결정은 이 문서를 고쳐 기록한다.

## 5. 검증

* d3d8·kernel probe, CTest(양쪽 모드: 기본, `REXBOX_GL_VAO=single`).
* reCT3 주행 비교(§3), 그림이 같은지 눈으로 확인.

# Design: the VAO bind cost in dense scenes (issue #78)

Status: design (step 1: an experiment switch). Consumer: reexec/reCT3#41. Earlier: [i023 draw CPU cost](20261021-i023-draw-cpu-cost.md), [i076 GL time](20261107-i076-gl-call-time.md).

## 1. Requirement

In a Crazy Taxi 3 drive (Win32 x86 Release, RTX 4090), `REXBOX_GL_CALLS=time` shows that nearly all GL driver time in dense scenes is `glBindVertexArray`, and that one bind costs more as the draw count grows:

| Draws/frame | fps | cpu ms/frame | GL ms/frame | `glBindVertexArray` ms (calls) |
|---|---|---|---|---|
| 900 | 59.0 | 7.55 | 1.41 | 0.89 (870) |
| 999 | 50.4 | 10.13 | 3.39 | 2.75 (951) |
| 1584 | 30.6 | 17.37 | 7.44 | 6.66 (1528) |

Every other GL call together stays under 0.8 ms per frame.

## 2. Today's structure (#23, `7634f9e`)

* Each cached vertex range (`g_vertex_ranges`) has its own VAO (`CachedRange::array`). `PrepareVertexData` binds it, and a changed range respecifies its storage with `glBufferData`.
* Each cached index range (`g_index_ranges`) has its own buffer. `BindElementBuffer` switches the bound VAO's element binding to it just before the draw.
* Uncached vertices use the stream VAO (`g_stream_array`) and the stream buffer.
* So in dense scenes nearly every draw binds another VAO and changes that VAO's element binding: 2810 `glBindBuffer` per frame in the 1584-draw window.
* #23 measured this as a small win (attributes −1.0 ms, VAO binds +0.8 ms). On this driver and these scenes it is now the largest single cost.

## 3. Step 1: the experiment switch `REXBOX_GL_VAO`

It tells apart what the driver charges for. The default stays as it is.

* `range` (the default, no variable): today's VAO per range.
* `single`: every draw uses the one stream VAO (the path before #23).
  * `PrepareVertexData` binds `g_stream_array` instead of the range's VAO, and binds the range's buffer to `GL_ARRAY_BUFFER`.
  * Attribute pointers are sent again only when the buffer or offset changed, through the existing comparison in `SetAttribute`.
  * The element binding is likewise sent only when it changes on that one VAO, through the existing `BindElementBuffer`.
  * No per-range `CachedRange::array` is made.
* The switch is read once at start-up, before the first draw, so the paths never mix.

Measurement: compare `range` and `single` over the same scenes in a reCT3 drive (`REXBOX_GL_CALLS=time REXBOX_D3D8_PROFILE=600`):
* GL time by entry point: `glBindVertexArray`, `glVertexAttribPointer`, `glBindBuffer`;
* the phase times: upload, attributes;
* fps and cpu in the dense stretches.

## 4. Step 2 (depending on step 1)

* If `single` wins, make it the default and decide whether to remove `range`. Whether the same holds on GLES 3.0 and WebGL 2 remains open.
* If `single` is costly too (resending pointers), consider GL 4.3 / ES 3.1 vertex attribute binding: one VAO per layout and `glBindVertexBuffer` per draw.
* The decision is recorded by revising this document.

## 5. Verification

* The d3d8 and kernel probes and CTest, in both modes (the default and `REXBOX_GL_VAO=single`).
* The reCT3 drive comparison (section 3), with a visual check that the picture is the same.
