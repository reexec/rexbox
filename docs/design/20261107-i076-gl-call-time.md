# 설계: 프레임당 GL 드라이버 시간 (`REXBOX_GL_CALLS=time`, issue #76)

상태: 설계. 소비자: reexec/reCT3#41(밀집 장면의 CPU 비용). 관련: #65(두 번째 게스트 스레드의 GL 작업), [i023 draw CPU 비용](20261021-i023-draw-cpu-cost.md).

## 1. 요구사항

Crazy Taxi 3의 밀집 주행 장면(draw 1100~1300개)에서 present하는 스레드는 프레임당 CPU 약 12 ms를 쓴다. 타이틀 코드가 약 3.8 ms이고, D3D8 HLE 단계가 약 7.5 ms다(upload 2.0, draw 1.5, constants 1.1, setup 1.0, indices 1.0 등).

이 단계 시간에는 우리 쪽 변환 작업(상태 키, 정점 구간 비교, 상수 묶기)과 GL 드라이버 안의 시간이 섞여 있고, 지금 프로파일로는 둘을 나눌 수 없다. 이 비율로 다음 단계가 정해진다.

* 7.5 ms 중 드라이버 시간이 크면: 호스트 렌더 스레드(#65의 답도 됨)가 그 시간을 타이틀 코드와 겹치게 할 수 있다.
* 대부분이 우리 변환이면: 그 작업을 줄이는 것이 먼저다.

## 2. 설계

* `REXBOX_GL_CALLS`에 값 `time`을 더한다.
  * `1`(또는 `time`이 아닌 0 아닌 값)은 지금처럼 횟수만 센다.
  * 변수가 없으면 아무것도 바뀌지 않는다. 래퍼도 설치되지 않는다.
* `time`이면 진입점마다 설치되는 기존 래퍼(`Counted<Id, F>::Call`)가 호출 전후에 `std::chrono::steady_clock::now()`를 읽고, 그 진입점의 누적 시간(ns)을 더한다.
  * GL은 컨텍스트가 현재인 한 스레드에서만 불리므로(#65) 카운터는 지금처럼 원자 연산 없이 둔다.
  * 반환값이 `void`인 진입점과 아닌 진입점을 모두 다룬다.
* 시작할 때 타이머 비용을 잰다. 빈 `now()` 쌍을 여러 번(예: 10000번) 재서 한 쌍의 평균 ns를 구하고, 첫 보고에 한 번 출력한다.
* 프로파일 창(`REXBOX_D3D8_PROFILE=<n>`)마다 횟수 줄에 더해 다음 줄을 출력한다.
  ```
  [d3d8 profile] gl time 6.12 ms/frame in 14210 calls (timer 0.38 ms/frame), 61% of cpu: DrawElements 1.80 (1240) BufferSubData 1.10 (2480) ...
  ```
  * GL 시간 합계(ms/프레임)와 호출 수를 쓴다.
  * 타이머 보정 추정치(호출 수 × 한 쌍 비용)를 쓴다.
  * 같은 창의 프로파일 `cpu`(present하는 스레드의 프레임당 CPU) 대비 비율을 쓴다.
  * 시간이 많은 진입점 16개까지(ms/프레임과 호출 수/프레임)를 쓴다.
* `TakeGlCallCounts`는 이름·횟수·시간을 함께 돌려주도록 넓힌다. 횟수 줄은 지금 그대로 둔다.

## 3. 비용

* 기본(변수 없음)과 `1`의 경로는 바뀌지 않는다.
* `time`은 진단 전용이다. 호출마다 시계 읽기 두 번이 더해진다(Windows는 QPC, 수십 ns).

## 4. 검증

* d3d8·kernel probe와 CTest.
* reCT3에서 `REXBOX_GL_CALLS=time REXBOX_D3D8_PROFILE=600`으로 West Coast 주행(`scripts/drive_west_coast.ps1`)을 돌려 밀집 장면의 줄을 읽는다.
* 같은 장면을 `REXBOX_GL_CALLS` 없이 돌려 fps가 크게 변하지 않는지(진단의 교란) 비교한다.

# Design: GL driver time per frame (`REXBOX_GL_CALLS=time`, issue #76)

Status: design. Consumer: reexec/reCT3#41 (the CPU cost of dense scenes). Related: #65 (GL work from a second guest thread), [i023 draw CPU cost](20261021-i023-draw-cpu-cost.md).

## 1. Requirement

In Crazy Taxi 3's dense driving scenes (1100–1300 draws) the presenting thread spends about 12 ms of CPU per frame: about 3.8 ms of title code and about 7.5 ms in the D3D8 HLE phases (upload 2.0, draw 1.5, constants 1.1, setup 1.0, indices 1.0, ...).

Those phases mix our own translation work (state keys, vertex-range compares, constant packing) with time spent inside the GL driver, and the profile cannot tell them apart today. The split decides the next step:

* if driver time is a large share of the 7.5 ms, a host render thread (which would also answer #65) can overlap it with the title's code;
* if most of it is our translation, cutting that work comes first.

## 2. Design

* `REXBOX_GL_CALLS` gains the value `time`.
  * `1` (or any nonzero value other than `time`) counts calls as now.
  * Without the variable nothing changes, and no wrapper is installed.
* With `time`, the existing per-entry-point wrapper (`Counted<Id, F>::Call`) reads `std::chrono::steady_clock::now()` before and after the call and adds the difference (ns) to that entry point's total.
  * GL is called only on the one thread where the context is current (#65), so the counters stay non-atomic as now.
  * Entry points that return `void` and those that return a value are both handled.
* At start-up the timer's own cost is measured: many (e.g. 10000) empty `now()` pairs give the average ns per pair, printed once with the first report.
* Each profile window (`REXBOX_D3D8_PROFILE=<n>`) prints, after the count line:
  ```
  [d3d8 profile] gl time 6.12 ms/frame in 14210 calls (timer 0.38 ms/frame), 61% of cpu: DrawElements 1.80 (1240) BufferSubData 1.10 (2480) ...
  ```
  * the GL time total (ms per frame) and the number of calls;
  * the timer correction estimate (calls × cost of one pair);
  * the share of the same window's profile `cpu` (the presenting thread's CPU per frame);
  * up to 16 entry points with the most time (ms per frame and calls per frame).
* `TakeGlCallCounts` widens to return the name, count and time together; the count line stays as it is.

## 3. Cost

* The default path (no variable) and `1` are unchanged.
* `time` is a diagnostic: each call gains two clock reads (QPC on Windows, tens of ns).

## 4. Verification

* The d3d8 and kernel probes, CTest.
* In reCT3, a West Coast drive (`scripts/drive_west_coast.ps1`) with `REXBOX_GL_CALLS=time REXBOX_D3D8_PROFILE=600`, reading the lines of the dense scenes.
* The same scenes without `REXBOX_GL_CALLS`, to check that the frame rate does not change much (the diagnostic's own disturbance).
