# 작업 로그: 커널 대기가 아닌 대기를 알리는 C API (issue #87)

작업 지시: [20261123-i087](../work-orders/20261123-i087-guest-wait-c.md) · 설계: [20261123-i087](../design/20261123-i087-guest-wait-c.md)

## 한 일

1. `245ed3f`(Antigravity 구현, Claude 설계·검토): `guest_lock.h`의 C 부분에 `rexbox_guest_wait_begin(const char* what)`과 `rexbox_guest_wait_end(void)`를 더했다. 각각 `runtime::NoteWaitBegin(what, nullptr, 0, false, -1)`과 `runtime::NoteWaitEnd()`를 부른다. 그래서 잠금 내려놓기, 중첩, stall 보고, #80의 대기 합계가 커널 대기와 같이 동작한다.
2. kernel probe에 확인 3개(`ProbeGuestWait`)를 더했다.
   * 잠금을 쥔 스레드가 대기 안에 있는 동안, 다른 스레드가 시한(2000 ms) 없이 같은 잠금에 들어갔다가 나온다.
   * 대기가 끝나면 원래 스레드가 잠금을 다시 쥔다.
   * 그 스레드가 나간 뒤에야 다른 스레드가 들어간다.

# Work log: a C API to announce a wait that is not a kernel wait (issue #87)

Work order: [20261123-i087](../work-orders/20261123-i087-guest-wait-c.md) · Design: [20261123-i087](../design/20261123-i087-guest-wait-c.md)

## Done

1. `245ed3f` (implemented by Antigravity, designed and reviewed by Claude): `rexbox_guest_wait_begin(const char* what)` and `rexbox_guest_wait_end(void)` join the C part of `guest_lock.h`. They call `runtime::NoteWaitBegin(what, nullptr, 0, false, -1)` and `runtime::NoteWaitEnd()`, so putting the locks down, nesting, the stall report and #80's wait totals behave as for a kernel wait.
2. Three checks in the kernel probe (`ProbeGuestWait`):
   * while the lock holder is inside the wait, another thread enters and leaves the same lock without the timeout (2000 ms);
   * after the wait the holder owns the lock again;
   * the other thread enters only once the holder leaves.

## Verification

* rexbox Release with 0 warnings, CTest 4/4, kernel probe 106 checks with 0 failures (the coder's report).
* Consumer reexec/reCT3#52 wraps CRI's safe-thread handshake (`000B3060`) in this wait: 48 hidden demo runs with no deadlock, stall, lock timeout or music stop (one deadlock in 48 before the fix); a drive at 59.5–59.8 fps.
