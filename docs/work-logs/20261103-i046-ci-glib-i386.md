# 작업 로그: CI의 Linux x86 패키지 설치 실패 (issue #46)

작업 지시: [20261103-i046](../work-orders/20261103-i046-ci-glib-i386.md)

## 원인 (**확인됨**, 러너에서 진단)

1. 2.80.0-6ubuntu3.10의 `libglib2.0-dev`는 `python3 | qemu-user | qemu-user-static`와 `libglib2.0-dev-bin-linux (= 3.10)`에 의존한다. `libglib2.0-dev-bin-linux`는 amd64 `libglib2.0-dev-bin`(`Multi-Arch: foreign`)이 제공하는 이름이다. `libpulse-dev:i386`이 이 i386 `libglib2.0-dev`를 끌어온다.
2. i386 패키지 하나씩(`libglib2.0-dev:i386`과 함께) 설치를 시뮬레이션하면 17개 모두 풀린다. apt는 대안으로 amd64 `qemu-user`를 고른다.
3. 목록 전체를 한 번에 주면, 해결기는 대안 `python3`를 i386 `python3`로 풀려고 한다. 이것은 러너의 amd64 Python과 충돌해 amd64 python 패키지 51개를 깨뜨린다. 해결기는 결국 포기하고, 남는 메시지는 `libglib2.0-dev:i386 : Depends: libglib2.0-dev-bin:i386 … held broken packages`다. 그래서 겉으로 보이는 메시지만으로는 원인을 알 수 없었다.
4. WSL2 Ubuntu 24.04에서는 재현되지 않았다. glib 개발 패키지(3.8)가 이미 설치되어 있어서 같은 요청이 그대로 풀렸다.
5. amd64 `libglib2.0-dev-bin`만 먼저 설치해서는 고쳐지지 않았다(같은 실패). `python3` 대안이 원인이었다.

## 한 일

* `ci.yml`, `release.yml`: x86 작업이 i386 목록 전에 `libglib2.0-dev-bin qemu-user`(amd64)를 설치한다. 그 이유를 주석에 적었다.
* `docs/guides/linux-setup-and-build.md`: i386 설치에 같은 선행 설치를 더했다.

# Work log: the CI's Linux x86 package install fails (issue #46)

Work order: [20261103-i046](../work-orders/20261103-i046-ci-glib-i386.md)

Cause (**confirmed** by diagnostics on the runner): glib 2.80.0-6ubuntu3.10's `libglib2.0-dev` depends on `python3 | qemu-user | qemu-user-static` and on `libglib2.0-dev-bin-linux (= 3.10)`, a name the amd64 `libglib2.0-dev-bin` (`Multi-Arch: foreign`) provides; `libpulse-dev:i386` pulls in the i386 `libglib2.0-dev`. Simulated one at a time (with `libglib2.0-dev:i386`), all 17 i386 packages resolve, apt taking the amd64 `qemu-user` alternative. Given the whole list at once, the resolver tries to satisfy the `python3` alternative with `python3:i386`, which conflicts with the runner's amd64 Python and breaks 51 amd64 Python packages; it then gives up, leaving only `libglib2.0-dev:i386 : Depends: libglib2.0-dev-bin:i386 … held broken packages`, a message that does not point at the cause. A WSL2 Ubuntu 24.04 did not reproduce it, its glib development packages (3.8) being installed already. Installing the amd64 `libglib2.0-dev-bin` alone first did not help; the `python3` alternative was the cause.

Done: `ci.yml` and `release.yml` install `libglib2.0-dev-bin qemu-user` (amd64) before the i386 list in the x86 jobs, with the reason in a comment; `docs/guides/linux-setup-and-build.md` adds the same step to the i386 install.

Verification: the branch's `ci.yml` (the fix, after three diagnostic runs) passes all six jobs (Win32 Debug and Release, Linux x64 and x86 Debug and Release).

Left: after the merge, the release workflow on the v0.0.21 tag and the Releases of v0.0.17–v0.0.20.
