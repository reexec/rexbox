# 작업 로그: 밀집 장면의 VAO 바인드 비용 (issue #78)

작업 지시: [20261107-i078](../work-orders/20261107-i078-vao-cost.md) · 설계: [20261107-i078](../design/20261107-i078-vao-cost.md)

## 한 일

1. 1단계: 실험 스위치 `REXBOX_GL_VAO=range|single`(`198d97c`). `single`은 캐시된 정점 구간도 스트림 VAO 하나로 그린다.
2. reCT3 주행으로 두 모드를 비교했다(설계 §4). 밀집 구간에서 `single`이 cpu를 프레임당 약 3.5~4.5 ms, GL 시간을 약 3.5 ms 줄였고, 59 fps 이상을 유지했다. 두 모드의 캡처도 정상이었다.
3. 2단계(`158477e`): 구간별 VAO(`CachedRange::array`), `DeleteArray`, `g_arrays`, 스위치를 걷어내 모든 draw가 VAO 하나를 쓰게 했다.
   * `ForgetBufferBindings`는 남겼다. 지워진 버퍼의 이름이 다시 쓰이면 그 VAO가 포인터와 요소 바인딩을 다시 보내야 하기 때문이다.
   * ARCHITECTURE의 환경 변수 목록에서 `REXBOX_GL_VAO`를 뺐다.
4. 역할: 코드는 Antigravity, 설계·검토·측정·문서는 Claude가 했다.

## 검증

* rexbox CTest 4/4(1단계는 두 모드 모두), Python 테스트 6/6. reCT3 Win32 x86 Release 빌드 경고 0, CTest 7/7. 모두 코더 보고다.
* reCT3 West Coast 주행(`REXBOX_GL_CALLS=time REXBOX_D3D8_PROFILE=600`, 21:9, 렌더 배율 4, MSAA 16x, RTX 4090):

| 빌드 | draw/프레임 | fps | cpu ms/프레임 | GL ms/프레임 |
|---|---|---|---|---|
| v0.0.27(구간별 VAO, #76 측정) | 1584 | 30.6 | 17.37 | 7.44 |
| 1단계 `range` | 1315~1586 | 54.2~56.7 | 12.68~14.27 | 4.09~4.58 |
| 1단계 `single` | 1265~1382 | 59.0~59.3 | 9.04~9.77 | 0.92~0.98 |
| 2단계(최종) | 1229~1297 | 59.2~59.3 | 8.28~8.93 | 0.86~0.92 |

* 최종 빌드 주행에서 스트림 멈춤·null 호출·잠금 시한·stall·GL 오류가 없었다.
* 주행마다 지나는 장면의 밀도가 달라 같은 draw 수끼리 비교했다. #76 측정의 30 fps 구간(1584 draw)은 이후 주행에서 다시 지나지 않았다.

# Work log: the VAO bind cost in dense scenes (issue #78)

Work order: [20261107-i078](../work-orders/20261107-i078-vao-cost.md) · Design: [20261107-i078](../design/20261107-i078-vao-cost.md)

## Done

1. Step 1: the experiment switch `REXBOX_GL_VAO=range|single` (`198d97c`); `single` draws cached vertex ranges through the one stream VAO too.
2. Compared both modes in reCT3 drives (design section 4). In dense stretches `single` cut the CPU per frame by about 3.5–4.5 ms and the GL time by about 3.5 ms, and held 59 fps or more. The captures were correct in both modes.
3. Step 2 (`158477e`): the per-range VAOs (`CachedRange::array`), `DeleteArray`, `g_arrays` and the switch were removed, so every draw uses one VAO.
   * `ForgetBufferBindings` stays: when a deleted buffer's name comes back, the VAO must send its pointers and element binding again.
   * `REXBOX_GL_VAO` was removed from ARCHITECTURE's list of environment variables.
4. Roles: Antigravity wrote the code; Claude designed, reviewed, measured and wrote the documents.

## Verification

* rexbox CTest 4/4 (step 1 in both modes), Python tests 6/6; reCT3 Win32 x86 Release with 0 warnings and CTest 7/7. All of these are the coder's report.
* reCT3 West Coast drives (`REXBOX_GL_CALLS=time REXBOX_D3D8_PROFILE=600`, 21:9, render scale 4, MSAA 16x, RTX 4090):

| Build | Draws/frame | fps | cpu ms/frame | GL ms/frame |
|---|---|---|---|---|
| v0.0.27 (VAO per range, #76's measurement) | 1584 | 30.6 | 17.37 | 7.44 |
| Step 1 `range` | 1315–1586 | 54.2–56.7 | 12.68–14.27 | 4.09–4.58 |
| Step 1 `single` | 1265–1382 | 59.0–59.3 | 9.04–9.77 | 0.92–0.98 |
| Step 2 (final) | 1229–1297 | 59.2–59.3 | 8.28–8.93 | 0.86–0.92 |

* The final build's drive had no stream stop, null call, lock timeout, stall or GL error.
* Each drive passes scenes of different density, so the comparison is between similar draw counts. The 30 fps stretch of #76's measurement (1584 draws) did not come up again in later drives.
