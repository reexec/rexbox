# Work log: file rename — done (issue #14)

Work order: [20261021-i014-file-rename](../work-orders/20261021-i014-file-rename.md) · Design: [20261021-i014-file-rename](../design/20261021-i014-file-rename.md) · Consumer: reexec/reCT3#9

Done: how the consumer title's XAPI `MoveFileEx` fills `FILE_RENAME_INFORMATION` was confirmed in the lifted library code (design section 1) and recorded in kb section 5. In `kernel_file.cpp`, `ObjectName`'s root handling became `NameRelativeTo`, and `NtSetInformationFile` class 10 got `RenameFile`, which closes the streams of every handle open on the host file, renames it, and reopens them on the new path; `REXBOX_TRACE_FILES` prints `[kernel] rename`. `kernel_probe` gained `ProbeRename` (11 checks).

Verification: Win32 x86 Release builds with no errors; `rexbox_kernel_probe` passes 94 checks with no failure (83 before, plus 11); CTest 3/3. The consumer reCT3 (hidden, 100 s) logs `rename \Device\Harddisk0\Partition5\tmp -> \??\Z:\_bank10.mdl -> 00000000`, the open after it succeeds, and the asset's scene (an indoor car park: floor, ceiling, walls, pillars) is drawn. The cache file is not a plain copy of the disc asset (13,115,392 against 15,849,024 bytes, different from the first byte): the title processes it on the way.
