# 작업 로그: YUY2/UYVY 텍스처와 캡처의 world/view 변환 (issue #58)

소비자: reexec/reEXCEED#4. 작은 변경이라 설계와 작업 지시는 이 로그로 갈음한다.

## 한 일

* `d3d8_texture_format`: `kYuy2` = 0x24, `kUyvy` = 0x25(XDK의 D3DFMT 값, **추정**)를 선형 16비트로 등록하고, 두 픽셀이 한 크로마 쌍을 나누는 디코드(BT.601 비디오 범위 16~235, **추정**)를 더했다.
* `d3d8_capture`: 고정 기능 그리기 줄에 projection과 함께 view, world 행렬, SetModelView·합성 행렬 여부를 쓴다.

## 검증

* Win32 x86 Release(reEXCEED 트리): 오류 0, 경고 0.
* reEXCEED: `texture upload: format 24 640x480, 1 level(s), linear (texel coordinates)`. 게스트 메모리의 그 텍스처에는 실제 YUY2 값이 있다(동영상 디코딩이 된다). 그림은 아직 검다: 캡처의 `owner` 그림이 전부 0이라 어느 그리기도 픽셀을 쓰지 못한다. view·world는 항등, projection은 `1/384, 1/288`에 x·y 이동이 없는 정사영으로, 픽셀 좌표(−0.5~639.5)의 정점이 화면에 맞게 놓이지 않는다(**미확정**: 행렬이나 정점 해석의 차이, 다음 단계).
